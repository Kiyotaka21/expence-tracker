# API

Поштучное описание REST-ручек. Общая картина — [architecture.md](architecture.md), поля
таблиц — [database.md](database.md).

Живая документация: **http://localhost:4000/api/docs** (Swagger). Она генерируется из тех
же zod-схем, что и валидация, поэтому расходиться с кодом не может. Этот файл нужен там,
где Swagger молчит: почему ручка ведёт себя так, а не иначе, и что именно означает
конкретный код ошибки.

## Общее для всех ручек

**Базовый URL:** `http://localhost:4000/api` (глобальный префикс `/api` задан в `main.ts`).

**Аутентификация.** Закрыто по умолчанию: `JwtAuthGuard` зарегистрирован глобально,
открытые маршруты помечены `@Public()`. Токены ходят в httpOnly cookie, заголовок
`Authorization` не используется. Запросы с фронтенда идут с `credentials: 'include'`.

| Открыто без сессии                                                          | Требует access-cookie |
| --------------------------------------------------------------------------- | --------------------- |
| `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`, `/health` | всё остальное         |

`refresh` и `logout` помечены `@Public()`, но закрыты своим `JwtRefreshGuard`: они читают
не access-, а refresh-cookie.

**Ограничение частоты.** Глобально `ThrottlerGuard`: 120 запросов в минуту. У
`/auth/register` и `/auth/login` своя планка — 10 в минуту. Превышение даёт **429**;
текст приходит по-английски (это сообщение самого `ThrottlerGuard`), и переводит его уже
фронтенд.

**Валидация.** Тело, query и параметры пути проверяет глобальный `ZodValidationPipe` по
схемам из `@expence/contracts`. Ошибка валидации — **400** с телом:

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "errors": [{ "code": "too_big", "path": ["limit"], "message": "..." }]
}
```

Обратите внимание: `message` здесь английский и техничный, а осмысленный текст лежит в
`errors[].message`. Доменные ошибки (401, 404, 409) API отдаёт по-русски, и веб показывает
их как есть — расхождение известное.

**Формат остальных ошибок** — стандартный для Nest:

```json
{ "statusCode": 404, "message": "Транзакция не найдена", "error": "Not Found" }
```

**Ошибки Prisma** переводит `AllExceptionsFilter`: `P2002` (нарушение уникальности) → 409
«Запись с такими данными уже существует», `P2025` (запись не найдена) → 404 «Запись не
найдена». Всё остальное — 500 с записью стека в лог.

**Владение записями.** Все выборки ограничены `userId` из токена. Чужая запись
неотличима от несуществующей: наружу уходит **404, а не 403** — иначе по коду ответа можно
было бы перебором нащупать чужие id.

**Суммы — всегда строки** (`"1240.50"`). В БД `Decimal(12,2)`, и превращать его в float
по пути к клиенту нельзя. На входе принимается и число, и числовая строка.

**Даты — ISO-строки** (`"2026-09-02T12:00:00.000Z"`).

## `auth`

### `POST /api/auth/register` — регистрация и вход

Открыт. 10 запросов в минуту. Регистрация сразу выдаёт пару токенов — отдельного входа
после неё не требуется.

**Тело:**

| Поле       | Тип    | Обязательно | Ограничения                                         |
| ---------- | ------ | ----------- | --------------------------------------------------- |
| `email`    | string | да          | валидный email, ≤254, приводится к нижнему регистру |
| `password` | string | да          | 8–128 символов                                      |
| `name`     | string | нет         | 1–120 символов после trim                           |

**Ответ 201:** `AuthUser` — `{ id, email, name, createdAt }`. Хеш пароля наружу не
попадает никогда. Плюс два `Set-Cookie`.

**Ошибки:** 400 — тело не проходит схему. **409** — «Пользователь с таким email уже
зарегистрирован». 429 — больше 10 попыток в минуту.

### `POST /api/auth/login` — вход

Открыт. 10 запросов в минуту.

**Тело:** `email`, `password` (здесь пароль проверяется только на непустоту — правило
длины применяется при регистрации).

**Ответ 200:** `AuthUser` + два `Set-Cookie`.

**Ошибки:** **401** «Неверный email или пароль» — одинаково и для неизвестного email, и
для неверного пароля. Пароль хешируется даже когда пользователь не найден: иначе время
ответа выдавало бы, зарегистрирован ли email. 429 — больше 10 попыток в минуту.

### `POST /api/auth/refresh` — обновить пару токенов

Читает `refresh_token` из cookie (путь `/api/auth`). Тела нет.

**Ответ 200:** `{ "message": "Токены обновлены" }` и два новых `Set-Cookie`.

**Что происходит:** старая сессия в `refresh_sessions` гасится (`revokedAt`), создаётся
новая с новым `id`. Это ротация, а не продление: один refresh-токен срабатывает ровно один
раз.

**Ошибки:** **401** в трёх случаях, и текст у них разный:

- `Некорректный refresh-токен` — cookie нет, подпись не сходится или в payload нет `sid`;
- `Refresh-сессия недействительна` — сессии нет, истёк `expiresAt` или хеш токена не
  совпал с `tokenHash`;
- `Refresh-сессия отозвана` — токен уже использован. Это трактуется как утечка, поэтому
  **гасятся все живые сессии пользователя**, а не только эта. Пользователя выбьет со всех
  устройств — так и задумано.

### `POST /api/auth/logout` — выход

Гасит текущую refresh-сессию и чистит обе cookie. Другие сессии пользователя не трогает.

**Ответ 200:** `{ "message": "Сессия завершена" }`.

**Ошибки:** 401 — refresh-cookie нет или она невалидна.

### `GET /api/auth/me` — текущий пользователь

Требует access-cookie.

**Ответ 200:** `AuthUser`.

**Ошибки:** 401 — нет валидной access-cookie либо пользователь удалён из БД, а токен ещё
живой.

## `transactions`

Все ручки требуют access-cookie. 401 и 429 возможны у каждой и ниже не повторяются.

### `GET /api/transactions` — список с фильтрами и пагинацией

**Query:**

| Параметр     | Тип                 | По умолчанию | Ограничения                       |
| ------------ | ------------------- | ------------ | --------------------------------- |
| `page`       | number              | 1            | целое ≥ 1                         |
| `limit`      | number              | 20           | целое 1–100                       |
| `categoryId` | uuid                | —            | фильтр по категории               |
| `type`       | `INCOME`\|`EXPENSE` | —            | фильтр по типу                    |
| `from`       | ISO datetime        | —            | нижняя граница, **включительно**  |
| `to`         | ISO datetime        | —            | верхняя граница, **включительно** |

Фильтры комбинируются через «И». Сортировка фиксированная: `occurredAt DESC`, при
равенстве — `createdAt DESC` (параметра сортировки нет).

**Ответ 200:**

```json
{
  "items": [
    {
      "id": "…",
      "amount": "2340.90",
      "type": "EXPENSE",
      "currency": "RUB",
      "occurredAt": "2026-09-02T12:00:00.000Z",
      "note": "Супермаркет",
      "category": {
        "id": "…",
        "name": "Продукты",
        "color": "#16a34a",
        "icon": "shopping-cart",
        "createdAt": "…"
      },
      "createdAt": "…"
    }
  ],
  "total": 13,
  "page": 1,
  "limit": 20
}
```

`total` — количество записей **под текущий фильтр**, а не длина `items`. Пустая выборка —
это пустой `items` и `total: 0`, а не 404.

**Ошибки:** 400 — `limit` больше 100, неверный UUID категории, `from`/`to` не ISO-датой,
`type` вне перечисления.

### `GET /api/transactions/summary` — сводка за месяц

Объявлена **до** `:id`: Nest сопоставляет маршруты по порядку, и параметр перехватил бы
слово `summary`.

**Query:**

| Параметр   | Тип    | Обязательно | Ограничения             |
| ---------- | ------ | ----------- | ----------------------- |
| `month`    | number | да          | целое 1–12              |
| `year`     | number | да          | целое 2000–2100         |
| `currency` | enum   | нет, `RUB`  | `RUB` \| `USD` \| `EUR` |

Месяц и год обязательны намеренно: умолчания скрыли бы, за какой период пришли цифры.

**Ответ 200:**

```json
{
  "month": 9,
  "year": 2026,
  "currency": "RUB",
  "income": "157000.00",
  "expense": "67941.10",
  "balance": "89058.90",
  "byCategory": [
    {
      "category": { "id": "…", "name": "Продукты", "…": "…" },
      "type": "EXPENSE",
      "total": "7531.70"
    },
    { "category": null, "type": "INCOME", "total": "157000.00" }
  ]
}
```

**Что важно знать:**

- **Считается по одной валюте.** Складывать рубли с долларами нельзя, курсов в проекте
  нет — записи в других валютах в сводку просто не попадают.
- **Границы месяца берутся в UTC.** В БД `timestamp(3)` без зоны, и смешивание с локальным
  временем давало бы разные итоги на разных машинах.
- **`balance` = `income − expense`**, поэтому может быть отрицательным.
- **`byCategory` разбит и по категории, и по типу**: доходы и расходы по одной категории —
  две разные строки. `category: null` — операции без категории.
- **Месяц без операций даёт нули**, а не 404 и не пустой объект: `income`, `expense`,
  `balance` равны `"0.00"`, `byCategory` пуст.

**Ошибки:** 400 — `month`/`year` не переданы либо вне диапазона, валюта вне перечисления.

### `GET /api/transactions/:id` — одна транзакция

**Ответ 200:** объект `Transaction` (та же форма, что в `items`).

**Ошибки:** 400 — `id` не UUID. 404 «Транзакция не найдена» — записи нет либо она чужая.

### `POST /api/transactions` — добавить

**Тело:**

| Поле         | Тип            | Обязательно | По умолчанию  | Ограничения                                |
| ------------ | -------------- | ----------- | ------------- | ------------------------------------------ |
| `amount`     | number\|string | да          | —             | > 0, ≤ 9 999 999 999, не более двух знаков |
| `type`       | enum           | нет         | `EXPENSE`     | `INCOME` \| `EXPENSE`                      |
| `currency`   | enum           | нет         | `RUB`         | `RUB` \| `USD` \| `EUR`                    |
| `categoryId` | uuid\|null     | нет         | `null`        | категория должна принадлежать вам          |
| `occurredAt` | ISO datetime   | нет         | время сервера | —                                          |
| `note`       | string\|null   | нет         | `null`        | ≤ 500 символов после trim                  |

Умолчание `EXPENSE` совпадает с дефолтом колонки в БД.

**Ответ 201:** созданная транзакция.

**Ошибки:** 400 — сумма не положительная либо с тремя знаками, заметка длиннее 500
символов; отдельно **400 «Категория не найдена»**, если `categoryId` указывает на чужую
или несуществующую категорию. Здесь именно 400, а не 404: ненайденный ресурс запроса — сама
транзакция, а неверная категория — ошибка в теле.

### `PATCH /api/transactions/:id` — изменить

Частичное обновление: непереданные поля не трогаются. `categoryId` и `note` можно
обнулить, передав `null`.

**Ответ 200:** обновлённая транзакция.

**Ошибки:** 400 — `id` не UUID, поля не проходят схему, категория не найдена.
404 — транзакции нет либо она чужая.

### `DELETE /api/transactions/:id` — удалить

Удаление физическое, корзины нет.

**Ответ 204** без тела.

**Ошибки:** 400 — `id` не UUID. 404 — транзакции нет, она чужая или уже удалена
(повторное удаление тоже даёт 404).

## `categories`

Все ручки требуют access-cookie.

### `GET /api/categories` — категории пользователя

Пагинации нет: категорий у пользователя единицы. Сортировка — по имени, `ASC`.

**Ответ 200:** массив `Category` — `{ id, name, color, icon, createdAt }`. Служебные поля
(`userId`, `updatedAt`) наружу не отдаются.

### `POST /api/categories` — создать

**Тело:**

| Поле    | Тип          | Обязательно | Ограничения                      |
| ------- | ------------ | ----------- | -------------------------------- |
| `name`  | string       | да          | 1–60 символов после trim         |
| `color` | string\|null | нет         | HEX вида `#1f2937`, ровно 6 цифр |
| `icon`  | string\|null | нет         | ≤ 40 символов                    |

**Ответ 201:** созданная категория.

**Ошибки:** 400 — имя пустое или длиннее 60, цвет не HEX. **409** «Запись с такими данными
уже существует» — у пользователя уже есть категория с таким именем (уникальность
`(userId, name)` в БД, `P2002` переводит `AllExceptionsFilter`).

### `PATCH /api/categories/:id` — изменить

Частичное обновление. Ответ 200.

**Ошибки:** 400 — поля не проходят схему. 404 «Категория не найдена». 409 — имя занято
другой вашей категорией.

### `DELETE /api/categories/:id` — удалить

**Ответ 204** без тела.

**Важно:** транзакции этой категории **не удаляются** — у них проставляется
`categoryId = NULL` (`onDelete: SetNull`). В списке и сводке они окажутся в группе «без
категории».

**Ошибки:** 404 «Категория не найдена».

## `health`

### `GET /api/health` — живость сервиса и БД

Открыт, аутентификации не требует.

**Ответ 200:** `{ "status": "ok", "database": "up" }`. Проверка настоящая: выполняется
`SELECT 1`.

**Ошибки:** **503** «База данных недоступна» — запрос к PostgreSQL упал. Ошибка пишется в
лог.

## Как API потребляет фронтенд

Единственная точка выхода в сеть — `apps/web/src/shared/api/client.ts`:

- всегда `credentials: 'include'` — токены в httpOnly cookie;
- пустые значения query отбрасываются, так что `{ page: undefined }` не превратится в
  `?page=undefined`;
- **при 401 клиент один раз дёргает `/auth/refresh` и повторяет запрос**; если refresh не
  прошёл, ошибка уходит наверх. Рекурсии нет: повтор идёт с `allowRefresh = false`;
- любой не-2xx превращается в `ApiError` со `status`, `message` (из `payload.message`) и
  сырым телом в `details`.

Запросы и ключи кэша лежат в `entities/<сущность>/api`. У транзакций ключи устроены так,
что инвалидация по префиксу `['transactions']` гасит и списки, и сводку — после создания
или удаления операции пересчитывается и то, и другое.
