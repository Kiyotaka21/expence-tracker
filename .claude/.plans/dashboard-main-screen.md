# Главный экран трекера расходов

## Контекст

Сейчас `/dashboard` (`views/dashboard`) — три карточки сводки за месяц и больше ничего: чтобы добавить операцию или посмотреть историю, нужно уходить на `/transactions`, за категориями — на `/categories`, а профиль представлен строкой с именем в шапке. Нужен полноценный главный экран: меню (быстрое создание, фильтры, переключение разделов), профиль пользователя и список транзакций с пагинацией по 10.

Бэкенд для этого уже готов: `GET /api/transactions` принимает `page`/`limit`/`type`/`categoryId`/`from`/`to` и отдаёт `{items,total,page,limit}` (`apps/api/src/modules/transactions/transactions.service.ts:19`), `GET /api/auth/me` — профиль. **Контракты и API не меняются** — значит, и пересборка `@expence/contracts` не нужна. Правки в `apps/api` — только демо-транзакции в сидах, иначе пагинацию не на чем посмотреть.

Решения, согласованные с заказчиком: главный экран остаётся на `/dashboard` (`/` и proxy не трогаем), страницы `/transactions` и `/categories` живут дальше, а общие части переезжают в `widgets` — дубля таблицы не будет. Профиль — меню в шапке плюс карточка на экране, без редактирования (эндпоинтов для него нет).

## Шаг 1. Примитивы shadcn/ui

```bash
pnpm --filter web exec shadcn@latest add dropdown-menu dialog avatar tabs skeleton
```

Все пять есть в стиле `radix-nova` (проверено по реестру), поля `dependencies` у них пустые — новых npm-пакетов не появится, `radix-ui` уже в зависимостях. После установки: файлы должны лечь в `apps/web/src/shared/ui` (по `components.json`), а `apps/web/package.json` — остаться без изменений (CLI любит дописывать версии с кареткой, в репозитории версии закреплены точно).

`pagination` из реестра **не берём**: он построен на `<a href>` внутри `Button asChild`, а состояние страницы у нас в React, не в URL — ссылка без адреса ломает семантику и правый клик. Кнопки пагинации собираем на `Button` внутри виджета.

## Шаг 3. Слой `widgets` — четыре новых среза

Каждый срез: `ui/<name>.tsx` + `index.ts` с единственным экспортом.

**`widgets/transaction-list`** — ядро задачи. Клиентский компонент, props `{ pageSize?: number }` (по умолчанию 10).

- Состояние внутри виджета (`useState`): `page`, `type`, `categoryId`. Так оба экрана-потребителя остаются тонкими, а сброс фильтров не надо тащить через props. URL-состояние (`?page=2`) сознательно не делаем — тянет `useSearchParams`, Suspense-границу и синхронизацию трёх значений.
- `useTransactions({ page, limit: pageSize, type, categoryId })`; фильтры при изменении сбрасывают `page` в 1.
- Таблица — перенос разметки из `views/transactions/ui/transactions-page.tsx:56-104` (дата, тип, категория, комментарий, сумма, удаление), но категория теперь с `CategoryIcon`, а сумма — через `TransactionAmount`.
- Состояния: `isPending` → 10 строк `Skeleton` (ровно на страницу, чтобы высота не прыгала); `error` → `ErrorAlert`; пусто → «Пока ни одной транзакции», а при активных фильтрах — «Под фильтры ничего не подошло» с кнопкой сброса.
- Приватные компоненты того же среза: `ui/transaction-filters.tsx` (два `NativeSelect` — тип и категория из `useCategories()` — плюс «Сбросить») и `ui/transaction-pagination.tsx` (`Button` «Назад»/«Вперёд», окно номеров, подпись «Стр. X из Y», `aria-current` на активной).
- Крайний случай: удалили последнюю запись на последней странице — `total` уменьшился, страница стала пустой. Эффект по `Math.ceil(total / pageSize)` возвращает `page` в допустимые границы.

**`widgets/category-list`** — блок списка категорий из `views/categories/ui/categories-page.tsx:36-75` как есть: `editingId`, инлайновый `CategoryForm`, `DeleteCategoryButton`.

**`widgets/create-menu`** — «Создать» (`PlusIcon`) на `DropdownMenu`, пункты «Транзакция» и «Категория». Состояние `creating: 'transaction' | 'category' | null` открывает один `Dialog`, внутри — существующая `TransactionForm` или `CategoryForm`; закрытие по `onDone`. Композиция двух фич возможна только на уровне виджета: фичам импортировать соседний срез запрещено линтером.

**`widgets/profile-card`** — `Avatar` с инициалами, имя, email, «С нами с <`formatDate(createdAt)`>» и «Операций всего: N» из `useTransactions({ limit: 1 }).data?.total` (отдельный ключ кэша, одна дешёвая запись; инвалидация по `transactionKeys.all` обновляет счётчик сама).

## Шаг 5. Демо-данные

`apps/api/prisma/seed.ts` — после категорий добавить ~25 транзакций демо-пользователя за текущий и прошлый месяц (разные типы, категории, суммы), чтобы страниц было три, а сводка не пустая. Транзакции без естественного уникального ключа, `upsert` не применить, поэтому вставляем только если `prisma.transaction.count({ where: { userId } }) === 0` — иначе повторный `pnpm db:seed` наплодит дублей.

## Вне объёма (осознанно)

- Редактирование транзакции: `PATCH /api/transactions/:id` есть, но с веба не используется — отдельная фича `features/transaction/edit-transaction`.
- Редактирование профиля (имя, пароль) — нужны новые эндпоинты и контракты.
- Переключатель месяца в сводке, экспорт, графики, состояние списка в URL.

## Проверка

```bash
docker compose up -d
pnpm db:seed                      # демо-пользователь, категории и ~25 транзакций
pnpm dev                          # web:3000 + api:4000
```

Вход: `demo@expence.local` / `demo12345`, дальше на `/dashboard`:

1. В списке ровно 10 строк, подпись «Стр. 1 из 3», «Вперёд»/«Назад» переключают без мигания пустой таблицы, на первой и последней странице соответствующая кнопка заблокирована.
2. Фильтр по типу и по категории сужает список и сбрасывает страницу на 1; «Сбросить» возвращает всё.
3. Таб «Категории» — список с инлайновым редактированием и удалением; на `/categories` тот же виджет ведёт себя так же.
4. «Создать» → «Транзакция»: модалка, после сохранения она закрывается, а список, сводка и счётчик в профиле обновляются (инвалидация по `transactionKeys.all`).
5. Удаление последней записи на последней странице возвращает на предыдущую, а не показывает пустую таблицу.
6. Профиль: аватар в шапке открывает меню с email и «Выйти»; карточка показывает дату регистрации и число операций.
7. Проверить тёмную тему (тема следует ОС) и узкий экран: таблица скроллится внутри `overflow-x-auto`, фильтры переносятся.
8. `pnpm typecheck && pnpm lint && pnpm build` — линтер заодно проверит границы FSD (`no-restricted-imports`), это единственный барьер: CI в проекте нет.
